## Executive Summary & Altitude Verdict

**Verdict: WARNING (Architectural Simplification & Contract Realignment Required)**

The design document demonstrates strong high-altitude alignment in its core strategy:
1. **Root Problem Focus**: Solving festival outreach through an objective, calendar-driven greeting engine rather than legally precarious religious/community profiling under the DPDP Act.
2. **Pragmatic Sync Strategy**: Decoupling festivals from incremental `?since` queries in favor of atomic Dexie table replacement (`clear() + bulkPut()`), effectively dodging the sliding-window sync invalidation trap.
3. **Dependency Discipline**: Rejecting heavy external JavaScript calendar libraries (FullCalendar) in favor of a native Livewire 4 / Tailwind CSS month grid.

However, the design suffers from three architectural issues:
1. **YAGNI & Speculative Layers**: Introducing an unused domain service (`FestivalGreetingService`), a redundant Artisan command (`ImportIndianFestivalsCommand`), and speculative database fields (`card_template_key`).
2. **Client Contract Breakdown**: The document assumes the Call Reminder Studio (`mr.components.call-reminder-modal`) seamlessly accepts pre-filled card templates and greeting text via event dispatch, but inspection of `resources/js/mr-app.js` shows `openWithDetail()` hardcodes `selectedTextTemplateId = 'product_gratitude'`, lacks `template` parameter handling, and expects a full `doctor` object rather than a `doctorId`.
3. **Non-Existent Target File Paths**: Multiple files in the modification inventory point to incorrect/phantom directories (`Api/V1/SyncController.php`, `elos/dcr.blade.php`, `components/mr/doctor-profile.blade.php`).

## Critical Findings

### Finding 1 (Major): Contract Mismatch with Call Reminder Studio & Missing File in Inventory
* **Affected Scope:** Lines 259–266, 360–382, 511–515
* **Technical Rationale:**
  The plan specifies that tapping "Create Greeting Card" dispatches `window.dispatchEvent(new CustomEvent('open-call-reminder', { detail: { doctorId: ..., template: 'celebration', greetingText: ... } }))`.
  However, inspecting `resources/js/mr-app.js` reveals:
  - `openWithDetail(detail)` expects `detail.doctor` (the doctor object from Dexie), not `detail.doctorId`.
  - `openWithDetail` hardcodes `this.selectedTextTemplateId = 'product_gratitude'`, completely ignoring any custom or festive greeting text passed in `detail`.
  - There is no parameter mapping for `detail.template` to set `this.selectedImageTemplate = 'celebration'`.
  - Furthermore, `resources/js/reminder-cards/celebration.js` has static hardcoded text on the canvas plaque ("WARMEST WISHES & SINCERE REGARDS") and has no data slot for dynamic festival text. Dynamic festive greetings belong in the WhatsApp text payload generated by `resources/js/reminder-cards/text-engine.js`.
  - `resources/js/mr-app.js` is **omitted** from the File Inventory table (lines 360–382), leaving the studio integration physically incomplete.

### Finding 2 (Major): Unused Domain Service & YAGNI Abstraction Layer (`FestivalGreetingService`)
* **Affected Scope:** Lines 100, 344, 370, 445–455
* **Technical Rationale:**
  The design introduces `App\Services\FestivalGreetingService` featuring `getActiveObservancesForDate(?Carbon $evalDate, ?string $specialty)`.
  - **No caller exists on the backend**: In the MR field app (`/elos`), reps work **offline**, evaluating active observances client-side directly against IndexedDB (`Dexie.js`) via JavaScript date strings (lines 246–253).
  - **Sync doesn't use it**: In Phase 4 (lines 480–497), `SyncController::masterData` queries `FestivalDate::with('festival')` directly and performs its own mapping.
  - **Calendar doesn't need a dedicated service**: `getMonthGridData()` is standard view-model/page query logic for the Livewire component `App\Filament\Pages\FestivalsCalendar`.
  Creating a standalone domain service for a feature whose evaluations happen either in client-side IndexedDB or in a single Filament page introduces dead code and premature abstraction. Model scopes on `FestivalDate` and page methods are far simpler and conform to existing codebase conventions.

### Finding 3 (Major): Redundant CLI Command Duplicating Seeder (`ImportIndianFestivalsCommand`)
* **Affected Scope:** Lines 368–369, 417–443
* **Technical Rationale:**
  The plan introduces both `database/seeders/FestivalSeeder.php` and `app/Console/Commands/ImportIndianFestivalsCommand.php` (`php artisan festivals:import`). Both read `database/data/indian_festivals.json` and execute identical `updateOrCreate` logic with the `is_manually_adjusted` safeguard.
  Laravel already provides `php artisan db:seed --class=FestivalSeeder`. Adding a bespoke Artisan command that duplicates the seeder's exact logic violates DRY and YAGNI.

### Finding 4 (Major): Non-Existent Target File Paths in File Inventory
* **Affected Scope:** Lines 360–382, 505, 508
* **Technical Rationale:**
  The File Inventory cites three paths that do not exist in the codebase:
  - `app/Http/Controllers/Api/V1/SyncController.php` (Line 373) -> The actual controller is `app/Http/Controllers/Api/SyncController.php` (no `V1` directory).
  - `resources/views/elos/dcr.blade.php` (Line 376, 505) -> The actual view is `resources/views/mr/dcr.blade.php`.
  - `resources/views/components/mr/doctor-profile.blade.php` (Line 377, 508) -> The actual view is `resources/views/mr/doctors/show.blade.php`.

### Finding 5 (Nit): Speculative Database Column (`festivals.card_template_key`)
* **Affected Scope:** Lines 132, 397
* **Technical Rationale:**
  The `festivals` table defines `card_template_key` with default `'celebration'`. Non-Goals (line 45) explicitly state that custom card generators are deferred and all festivals will reuse `celebration.js`. Storing a column on every database record for an invariant value is speculative flexibility (YAGNI).

### Finding 6 (Nit): Altitude Drops into Implementation Weeds
* **Affected Scope:** Lines 246–253, 419–442, 480–497
* **Technical Rationale:**
  The specification embeds large blocks of concrete implementation code (24-line seeder loop, 18-line Eloquent mapping snippet, 8-line Javascript filter callback) in high-level architectural sections.

## YAGNI & Simplification Recommendations

1. **Eliminate `FestivalGreetingService.php`**: Move active date query logic into an Eloquent scope on `FestivalDate` and month-grid computation into `App\Filament\Pages\FestivalsCalendar`.
2. **Eliminate `ImportIndianFestivalsCommand.php`**: Keep dataset ingestion exclusively in `FestivalSeeder.php`.
3. **Formally Add `resources/js/mr-app.js` to File Inventory**: Update `openWithDetail(detail)` to accept `templateId` and `greetingText`.
4. **Correct Target File Paths**: Use `app/Http/Controllers/Api/SyncController.php`, `resources/views/mr/dcr.blade.php`, and `resources/views/mr/doctors/show.blade.php`.
5. **Drop `card_template_key` Column from `festivals` Schema**: Hardcode `'celebration'` in the sync payload or client handler until a second template exists.
